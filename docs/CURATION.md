# 筛选与版本契约

## 首批接受证据

人工路径：原审听包的 20 条 Qwen3 音频得到逐条“全部正确”的确认；匿名 JSONL 收据绑定原包 SHA-256、每条 WAV SHA-256、文本、类别和关键词 ID。原收据字节保持不变。该结论只覆盖固定批次，不扩展到该声线将来的输出。

机器路径：固定 sherpa-onnx/中文 Zipformer CTC 的程序、模型和 tokens 哈希；对文本做 Unicode NFKC、去空白和标点后精确匹配。正例和负例都必须匹配其各自预期文本。未匹配是自动筛选不接受，不是已证实读错；已有人工真值不会被机器收据改写。

| ASR 资产 | SHA-256 |
| --- | --- |
| sherpa-onnx v1.13.8 离线程序 | `3cca8d3f4a7edc19717fe49aecceab632727ed6a11f230fb64037cdb284c184a` |
| Zipformer CTC int8 模型 | `e291b9c468b651e2697caa09bc684326c3addc6a019e78eb537cfd1a8248ca07` |
| tokens | `6fed8c6c248516f38e7faa19404b57413e8ce259f1cbc1fa4aebc86eac32fdfd` |

第一扩展批生成 24 条，ASR 接受 19 条；连续性筛选又排除 1 条，归档 18 条。开发回读批生成 8 条，ASR 接受 4 条并通过连续性检查，归档 4 条。未入选音频没有按原文本发布为合格数据。manifest 保留原生成清单与完整 ASR 收据的 SHA-256，发布收据仅覆盖本版本入选音频。

连续性规则用 10 ms RMS 帧，以峰值 RMS 的 1% 区分低能量帧；完整正例首末活动帧之间不得出现达到 120 ms 的连续低能量间隔。该规则只是本任务的小样本研究保护，可能错剔自然停顿，也不是音素强制对齐或通用发音质量标准。人工批次保留人工结论，工具不会把机器规则追溯覆盖到人工标签。

## 版本与切分

- `catalog.json` 固定每个版本的 manifest、审核收据和 splits 哈希；每条音频同时记录文件和 PCM 哈希。
- 发布后修改音频、标签或接受结论，应发布新版本并明确取代关系，保留旧版身份。
- 五种 Qwen3 声线在所有批次固定到相同 split。开发 A/B 已多次观察，只能用于探索性回读。
- 同源音频、同说话人/声线、增强派生跟随同一切分；按全仓检查重复 PCM，不能只检查单批。
- 生成器一致的开发集不能证明跨生成器泛化；合成集不能替代真人目标词、实际 AFE 或目标板资格。

## 核验与输入到训练

运行 `python3 -m tools.codex_assets verify`。将失败视为数据版本不可消费，先定位缺文件、格式、hash、收据或切分原因。训练端需要绑定本仓 Git commit 与 catalog SHA-256，并自行生成该算法所需 token 标签；本仓文本真值不绑定某个四 token 或整词 token 模型。

现有文本标签没有词结束时间；需要事件帧监督时另生成并人工/强制对齐验证，记录对齐器身份和时间误差。用唤醒模型自己的事件作为语音标签会形成循环验证，应保留独立转写/审核证据。

## 当前 catalog v2

来源、审核和声线切分规则现在由 catalog 的 source/review/split 配置提供；验证器不再把五个名字或某个 ASR hash 写死为全仓规则。split 的已观察状态和资格禁用也实际校验。当前支持范围仍是公开合成开发资产，扩展新类别需具体 schema/测试审查。固定消费使用唯一 exporter，见[资产架构](ASSET_ARCHITECTURE.md)。
