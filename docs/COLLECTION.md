# 语料收集、生成与场景派生

## 现成数据与真实语音

每个来源登记提供者、原始地址、精确版本、权利说明、原始包 SHA-256、说话人/会话标识、文本与实际语音的核验方式。先确认目标词、近邻或普通负例的标签语义，再筛选。原始来源的词汇相似度不能自动当作目标唤醒标签。

AISHELL3 在本项目原有训练池是由该来源相关 TTS 方案生成的 128 条音频，不等于 128 条真人实录目标词。HI-MIA-CW 曾用于真人近邻负例回读，应按真实说话人划分，音节等价筛选只用于负例；不能将“你好呀”等近音文字改标为正例。现阶段本仓保存这些来源的方法和研究结果索引，未上传其原音频。

收集真人目标词时，先记录知情授权与可公开范围，再保留匿名说话人、录音会话、房间、距离、角度、设备及 AFE 版本。未允许公开的原音频放受控存储；公开仓只记录脱敏索引。训练、开发与封存资格按真实人/会话分离；同一个人的增强样本不能跨切分。

## 合成生成

1. 固定生成器代码 commit、模型 revision、权重哈希、运行环境和参数。
2. 冻结文本矩阵：两条完整目标词、缺首“窝小窝”、重复近邻“你好你好”，再扩展缺尾、插字、相近音节与日常语句。
3. 固定声线/声音设计、seed、语速和风格；没有真实年龄/性别证据时只记录合成风格，不填写人口统计真值。
4. 原始输出保留来源采样率；规范化使用有记录的重采样器，不通过改 WAV 头伪造 16 kHz。
5. 每条生成即记录文件和解码 PCM 的 SHA-256。生成成功只进入 `incoming/`，经筛选后发布新数据版本。

同生成器不同声线、seed 和提示词属于同一模型家族；不同生成器也可能共享底座或训练来源，不能据此宣称完全独立。跨生成器开发应明确留出家族，避免在观察留出结果后继续称为盲测。

## 场景派生

先保存干净原声，再对训练侧原声生成距离衰减、房间脉冲响应、噪声/SNR、风扇、媒体播放、回声、增益和裁剪等受控派生。每条派生记录父 PCM SHA-256、变换程序身份、噪声/RIR 来源与哈希、seed 和全部参数。派生数据跟随父原声的切分。

模拟场景不是实际 AFE 或目标板录音。派生后的正例需重新检查完整性、停顿和削波，不能沿用原声收据直接判定合格。历史场景样本中的 Uncle_Fu 第一词曾被实听判为“沃”，该反馈属于对应场景批次；本仓发布的是此前明确审听的原始 20 条和独立 ASR 入选批次，未发布这些有争议的场景派生。

## 连续负例

除短片段外，应收集连续无目标词录音：静音、稳定设备噪声、风扇、音乐、对话、电视播放和混合背景。记录真实有效时长，按目标词不存在的审核结果标注。短负例拼接有边界和状态重置效应，不能冒充独立连续环境录音。FAR 统计应报告负例小时数、误触发计数及统计上界；零事件不意味着零风险。
