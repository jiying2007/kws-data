# 两个轻量因果原型：四次固定预算实验结果

日期：2026-09-30。结论：**两种结构都没有达到跨声线双词目标，不进入 C 导出/产品候选。**
FSMN 在两个 seed 都学会了 12 条训练片，资源设计更小；但未能稳定识别开发声线的两个词。
这支持继续研究新的小模型结构，不支持保留现有 RNN 为唯一方向，也不证明所试 CNN/FSMN 本身无法成功。

## 已执行的固定设计

- spec SHA-256：`c0022e6abee8555d1abfa982d7c947da8a662e09f5bc39c88fd41d1b2edf6dc5`
- 先通过独立 AI 代码/协议审核及 8 项因果、逐帧/分块、重置、mask、梯度测试，再启动四次训练
- A = 14,882 参数因果 depthwise temporal CNN；B = 11,954 参数低秩因果 FSMN
- 两结构 × seeds 1337/2346；Adam 0.001，batch 4，1000 steps，最后 checkpoint，无 epoch/threshold 选择
- 阈值固定 logit ≥0；C32维 logmel 特征；没有新增数据增强、前后补音或新 token/时刻标注
- 只使用 12 条人工审核训练片（6 正例/6 近邻）；人工开发 A/B 各 4 条，ASR22 条全部只读回测
- 全部都是已观察开发数据；人工开发声线 Serena/Eric 与训练声线分离，不能称独立真人盲测
- 每次实际训练及评分约 7.6–15.4 秒，四次均完整达到 1000 steps，没有超时、重试或额外训练

数据固定在 kws-data `2f9658ffa9568076ef547615c76861abed84f56e`，
catalog `27b590cdc325d48d2cf5e1293b8e431c815382be0219bc2e069d4e08896ee391`。
由其 canonical exporter 生成消费收据；42 条 WAV 在 C 特征提取前后核对 SHA，
3886 帧的顺序与无补音帧数规则逐条核验。

## 正确性与资源边界

训练前：8 项测试全部通过，准确参数/cache 数与设计一致；未来帧不影响过去输出；
序列、逐帧、不等长分块、重置、padding mask 与梯度检查通过。
训练后：4 个 checkpoint ×42 条音频再次核对不等长分块与整段前向，
最大绝对 logit 差分别约 `5.72e-6,5.72e-6,1.53e-5,7.63e-6`，
在预定 `atol=2e-6,rtol=2e-5` 下通过，所有阈值判断一致。
这排除了本次结果由已检查的分块状态路径差异解释，但不证明所有模型/数据处理问题都已排除。

- A：约0.718 MMAC/s，5952 float 时间缓存（23,808 bytes），FP32 参数59,528 bytes
- B：约0.586 MMAC/s，2880 float 时间缓存（11,520 bytes），FP32 参数47,816 bytes

以上都是公式和 PyTorch shape 验证，未包含前端/进程/工作区/内存访问，不是 SSC305 测量。
没有创建 C kernels、ABI、通用运行时或兼容层；不因原型失败增加产品维护负担。

运行环境：官方 CPU wheel `torch2.13.0+cpu`、Python3.12.14、NumPy2.5.2、CPU单线程，
MKLDNN关闭、deterministic algorithms开启。正式锁的 Python 为3.12.11，且此研究没有正式 OCI identity，
因此不声明正式训练环境等价。原始安装日志、wheel来源/hash报告和实际依赖 lock 都已保存。

## 补充：特征分布审查与下一次单一实验建议

`feature_audit.py` 为训练结束后的只读描述性检查，没有改模型、数据或阈值。
当前 C 前端对**每一帧的32个 mel 通道减去该帧通道均值，再乘固定配置增益**；
不存在由训练集拟合的每通道 mean/std，也没有全语料或逐句 CMVN。
本次输入沒有使用开发数据拟合任何归一化，所以不存在这一形式的数据泄漏；
但固定逐帧归一化也不能保证说话人、语速和静音比例分布一致。

人工 train/A/B 的观察值：

| 量 | train12条 | A4条 | B4条 |
| --- | ---: | ---: | ---: |
| 片长中位数 |1.92s|1.64s|1.08s|
| 特征总体标准差 |0.360|0.433|0.513|
| 帧能量高于−50dBFS比例 |43.1%|66.1%|84.0%|
| 按训练帧 mean/std 标准化后的通道均值偏移RMS |0|0.385|0.482|

最后一行仅用于描述，标准差 floor0.05，统计只拟合人审train；**未应用到任何模型**。
这些差异说明开发片更短、静音占比不同和特征分布存在偏移；没有证明它们造成漏检，
也不证明补一个 CMVN 就能解决。−50dBFS 只是描述性分桶，不是新增 VAD 或时刻标签。
每组仅少量声线，无法做可靠域差异显著性结论。详见 `feature-audit.json`。

### 建议下一步：一次轻量真实中文声学迁移对照，尚未启动

为避免重演同源场景扩增/259条 CTC 配方，建议保持 B 的11,954参数、C前端和弱片段任务，
把唯一研究变量换为“encoder 是否在获权真实中文上预训练”，不再加层/扫阈值。

- 数据候选：[MobvoiHotwords官方SLR87](https://www.openslr.org/87/)，页面标Apache-2.0，
  包含两个不同中文相关唤醒词与真实家庭负例；使用其 native labels，绝不改标为小窝词
- 先只读6.3MiB级资源索引，按speaker/source母录音分组冻结一个最多2560片、最多2小时的训练子集，
  正例/近邻或普通负例大致平衡；同一母录音多通道只能计一次，另留speaker-disjoint donor开发组
- 预训练 B 的两个donor词输出，最多2000steps、一个预声明seed，最后checkpoint，不看Qwen A/B选模型
- 丢弃donor词head，冻结48维encoder；只训练新的小窝二输出head。与“随机初始化但同样冻结的B encoder”
  做两seed head-only对照（1000steps、原人审12train、固定阈值0），共4个轻量head fits
- 评估保留人审A/B和ASR22分开；逐词命中与近邻并报，不因小样本合计分数选“架构赢家”
- 若预训练encoder相对随机冻结encoder不能跨两seed同时改善两个词且不增加近邻，则停止这条迁移配方；
  donor训练自身不收敛时首先报告，不延长预算或换subset后仍称同一实验

资源/权利前提：官方完整音频归档约**17GB**，不是小子集就可只下载小文件；
需先确认本地已有获权数据或资源/磁盘/下载方式，再采集。不能悄悄换来源不明的第三方镜像小包。
固定归档许可/版本/hash、人员与源录音切分、subset抽样种子；不公开再分发未审查原音频。
若需要完整17GB下载，先让父任务确认资源安排。此方案无需真人产品录音/实体板才开始，
但得到的软件迁移收益仍不能替代最终产品证据。

不直接引入大模型运行时或使用权利未明确的现成embedding权重；
