## Mero：首元音一致，词尾与 Hey 开头仍有差异

固定面板中有 8 条 Mero。两路对这 8 条的词内首元音均输出 **`ɛ`（8／8）**。词尾原始类别如下，`o`、`oː`、`oʊ` 和 `ɔ` 分别计数：

| Mero 末尾原始输出 | XLSR | LV60 |
| --- | ---: | ---: |
| `ɔ` | 7 | 0 |
| `o` | 0 | 6 |
| `oː` | 0 | 2 |
| 精确 `oʊ` | 0 | 0 |
| 未输出末尾元音，序列止于 `ɹ` | 1 | 0 |

最后一项是 af_bella slow 的**末尾元音未被解码**，不是捕获缺失。LV60 的 8 条 Mero 没有任何一条输出精确 `oʊ`；不能把 2 条 `oː` 写成 2 条 `oʊ`。

| Mero 的 Hey 原始 token 前缀 | XLSR | LV60 |
| --- | ---: | ---: |
| `h eɪ` | 4 | 2 |
| `t eɪ` | 3 | 3 |
| `h eː` | 0 | 1 |
| `h iː` | 1 | 2 |

因此，只有 af_sarah fast 和 am_michael fast 的 LV60 全句，在**描述性比较**中匹配既有 Mero 完整 phone 正则（2／8；旧 XLSR 为 0／8）。这是固定正则的字符串兼容性检查，不是完整 ASR、几何、声源组或训练准入重算。既有正则本来允许词尾 `o`，既有 normalizer 本来移除长度符号；本报告的原始输出表不应用该合并，更未将 `oː` 改成 `oʊ`。这 2 条没有获得新标签或权重。

## 对照词没有支持把 LV60 当作真值

| 观察位置 | 条数 | 原 XLSR token | 新 LV60 token |

| Memo 末尾 | 4 | `ɔ` ×4 | `o` ×2，`aʊ` ×1，`ɑ` ×1 |
| hello 的 O | 4 | `oʊ` ×1，`oː` ×3 | `oʊ` ×4 |
| open 的 O | 4 | `oʊ` ×3，`oː` ×1 | `oʊ` ×4 |
| door 在 `d` 后的末尾 token | 4 | `oː` ×4 | `ɔːɹ` ×1，`oːɹ` ×2，`oʊ` ×1 |

am_michael 的 **Open the door** 中，LV60 对 door 输出 `d oʊ`，而请求的 door 为 `/dɔɹ/`。这条当前同 PCM 对照必须与 Mero 结果一起报告：不能仅采用看起来更接近品牌目标的 LV60 词尾，忽略其在对照上的差异。完整序列 0／24 精确一致也不是识别准确率或合成失败率；两个观察器都没有人工发音真值地位。
